# Ранбук: как делать новое дело

Пошаговый процесс выпуска дела, собранный по опыту пилота «Синяя сова» (ноябрь 2026). Читают его планировщик (чат, где придумывается сюжет), агент-разработчик и владелец. Образец готового дела — [`docs/cases/case-001-blue-owl.md`](cases/case-001-blue-owl.md) и `public/cases/case-001-blue-owl/case.json`.

## Роли

| Кто                             | Что делает                                                                                                                                                       |
| ------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Владелец**                    | выбирает концепцию, утверждает сюжет и арт, утверждает голос и звучание, кладёт ключи API в секреты GitHub, проверяет на телефоне, собирает APK в Android Studio |
| **Планировщик** (отдельный чат) | 3 концепции → «библия дела» в формате `docs/cases/case-NNN-*.md`, промпты для арта, озвучки и музыки; ревью PR агента                                            |
| **Агент**                       | `case.json`, валидатор, код (если нужен), **весь арт** (AGENTS.md §4), подготовка аудио, тесты, документация                                                     |

## Шаг 0. Один раз перед вторым делом

- [x] **Несколько дел в коде.** Реестр встроенных JSON, список S03, загрузка по `caseId`, сохранение v4 и миграция старых партий. Проверка двух дел использует фикстуру только в e2e-сборке; второе настоящее дело добавляется отдельным PR. См. ADR-030.
- [ ] **Workflow озвучки.** `cartesia-sample.yml` привязан к удалённой ветке `codex/cartesia-narration`. Его надо переделать: запуск вручную с выбором дела.
- [x] **Вес исходников.** Новые исходники в `art/` — в Git LFS (ADR-027), проверка `npm run lfs:check` в CI. При упоре в лимиты GitHub — переезд на свой сервер или S3 по плану ADR-027.

## Шаг 1. Концепция (планировщик → владелец)

Планировщик предлагает **3 концепции** (промпт B.1 из `04-ai-prompts.md`), владелец выбирает одну.

Требования к концепции:

- Ветрогорск, наши дни, нуар, **рейтинг 12+**: без крови и натурализма, тела не показываем.
- **4 подозреваемых** из «труппы» (`05-art-bible.md` §3.4). Новые актёры — только если без них никак: каждый новый актёр = 6 портретов.
- Виновный не самый очевидный, но и не «из ниоткуда».
- Ключевые улики вместе доказывают **мотив + способ + возможность**.
- **Минимум 2 ложных следа.** У каждого невиновного есть алиби или объяснение, которое можно найти в игре.
- Не повторять пилот: другой тип места (не бар), другой способ, другой мотив.

## Шаг 2. «Библия дела» (планировщик)

Файл `docs/cases/case-NNN-<slug>.md` в формате пилота: брифинг, жертва, правда и поминутная хронология, мотивы и способы для обвинения, таблица фактов, локации и хотспоты, улики, подозреваемые, подсказки Шефа, объяснение финала.

Уроки пилота — обязательные правила:

1. **Документы — это сами документы, а не выводы детектива.** Билет: «Северск → Ветрогорск · Пт · Прибытие 22:10 · Пассажир: Лебедева О. В.», а не «Ольга приехала… хотя говорила…». Выводы живут только в фактах (блокнот). Валидатор запрещает совпадение текста документа с фактом.
2. **Ключевая улика не выдаётся мгновенно.** Минимум одна головоломка из двух улик в разных комнатах, как код сейфа: ежедневник «день рождения Совы» + дата на обороте фото → 1408. Замки, коды, детали — только из канона, без «тайников из ниоткуда».
3. **Point-and-click детали (ADR-019): 2–3 на дело.** Предмет найден → деталь надо найти самому (скол, подпись, пятно). Никакой подсветки и подсказок в тексте; факт открывается только после находки детали.
4. **Ложь после признания.** Если у вопроса `offlineQA` ответ — ложь по теме `hiddenTruth`, дай `afterBreak` с правдивым ответом (ADR-022). Иначе подозреваемый после признания снова врёт.
5. **Пунктуация.** Обычные русские точки. Никаких «; » между предложениями и «?.» (в пилоте 31 текст был испорчен автозаменой). Ответы — до 3 предложений, признания — до 4.
6. **У каждого подозреваемого 6–8 офлайн-вопросов.** Часть открывается только с уликой (`requiresClueId`) или фактом. Хотя бы один вопрос подталкивает к нужной комнате («Где Аркадий хранил важное?»).
7. **Подсказки Шефа: 3 штуки** с `afterRound` и `unlessAnyPlayerHas`. Они ведут к главным узким местам: головоломке, ключевой улике, подозреваемому, которого надо сломать.
8. **Ни имени виновного рядом со словами «убил/убийца»** в легендах и ответах, доступных ИИ (`04-ai-prompts.md`). Правда о тайне попадает в промпт только после слома (ADR-003).
9. **3 локации по 4–6 хотспотов, 10–14 улик.** Не все зоны с уликами: пустые зоны с атмосферным текстом нужны, иначе обыск угадывается.

Перед передачей агенту планировщик прогоняет самопроверку B.3 из `04-ai-prompts.md` (дыры, лёгкие пути, противоречия во времени) и исправляет найденное.

## Шаг 3. Реализация (агент, одна ветка от `main`, один PR)

1. **`case.json`** по `03-case-schema.md` (текущая версия схемы, `minAppVersion`). Новая механика — только через ADR, валидатор и миграцию.
2. **Валидатор зелёный:** решаемость, достижимость каждого ключевого факта, алиби невиновных, документы ≠ факты, пунктуация.
3. **e2e:**
   - кратчайшая победа в одиночку;
   - партия на 2 игрока с ошибочным обвинением;
   - каждая головоломка: верный и неверный код;
   - каждая деталь point-and-click;
   - `afterBreak`.
4. **Арт** — по AGENTS.md §4 и `05-art-bible.md`:
   - сначала список всех картинок в `art/ASSETS.md`;
   - генерация пачками: крупные планы → улики → новые актёры → реконструкция → обложка;
   - после каждой пачки — контакт-лист;
   - **никакого текста на картинках**: документы, номера, подписи рисует код;
   - переиспользовать труппу и, где возможно, локации;
   - примерный объём на дело: 3 локации, 9–12 крупных планов, 5–8 предметов, 3 реконструкции, обложка, плюс 6 портретов на каждого нового актёра.
5. **Координаты хотспотов** — через редактор S17 (debug-сборка), а не на глаз.
6. **Аудио — генерирует агент через ElevenLabs API (ADR-025), строго по одной попытке на каждый файл:**
   - **Музыка.** По умолчанию переиспользуются 5 треков пилота. Своя тема для дела — по желанию владельца: промпты в `AUDIO-PLAN.md`, **минимальная длина** (петля 60 с, финал 25–30 с), длина задаётся параметром API. Подготовка — `tools/prepare-music.py`.
   - **Звуковые эффекты** (дверь, сейф, шаги, бумага) — ElevenLabs Sound Effects, короткие (1–5 с). Интерфейсные звуки остаются синтезированными (`tools/generate-sfx.py`).
   - **Речь** (брифинг, 3 подсказки, объяснение, 3 подписи реконструкции) — смысл только из `case.json`; произносимая версия — в `content/narration/elevenlabs.json`, на экране текст не меняется. Нельзя озвучивать то, что меняется настройками (число раундов).
   - **Голоса — одни на всю игру (ADR-026):** рассказчик **Alex Bell** (`TUQNWEvVPBLzMBSVDPUA`), Шеф **Nester Surovy** (`pM78bgjPVk0JXtaEnFoj`), модель `eleven_v4`. Новый голос (например, для нового персонажа) — только после одобрения владельцем по одной пробной фразе.
   - **ЖЁСТКОЕ ПРАВИЛО: в произносимом тексте нет ни одной цифры.** Генератор откажется работать, если найдёт цифру. Автонормализация ElevenLabs для русского ненадёжна: путает падежи («тридцать один» вместо «одну») и читает время по-военному («двадцать ноль-ноль»). Пиши так, как сказал бы рассказчик:
     - время — «в восемь вечера», «в половине двенадцатого ночи», «без четверти полночь», «четверть первого»; точную минуту, если она ключ к разгадке, — «в двадцать три тридцать одну»;
     - возраст и количества — «пятидесяти двух лет», «четверо»; даты — «четырнадцатого августа»;
     - номера машин, коды, адреса — по-русски по символам: «вэ семьсот сорок два ка эс», «код один-четыре-ноль-восемь», «Портовая, двенадцать»;
     - скобки и сокращения — раскрыть: «(52)» → «пятидесяти двух лет», «О. В.» → «Ольга Викторовна» или без инициалов.
   - Падеж числа сверять глазами: «в двадцать три тридцать одну (минуту)», «до восьми вечера», «с одиннадцати».
   - **Перед генерацией** — список «файл · тип · длина · промпт» в devlog и PR. **После** — потраченные кредиты в devlog.
   - **Неудачный результат не перегенерировать молча.** Сообщить владельцу, что не так, и ждать решения.
7. **Документация:** STATUS (переписать), devlog, INDEX без пустой строки, MANUAL-TEST-QUEUE (пакет на дело), CHANGELOG (версия). **APK не собирать** (ADR-024): владельцу дать команды из HOWTO.

## Шаг 4. Ревью (планировщик)

Проверить ветку как в QA-проходе 2026-11-12:

- тесты и e2e;
- ручной проход в браузере 360×800: все экраны, «Назад», документы, головоломки, детали, финал;
- контакт-листы арта.

Найденное — одним списком агенту или исправить в той же ветке. Затем свести с `main` и влить.

## Шаг 5. Проверка владельцем (телефон)

Одна полная партия на 2–3 игрока и пакет MT нового дела:

- дело раскрывается без подсказок разработчика;
- головоломки понятны, детали находятся пальцем;
- нет текстов с опечатками и спойлерами;
- озвучка и музыка звучат;
- реальный ИИ-допрос с ключом: 3–5 вопросов на подозреваемого.

Замечания → один PR с исправлениями.

## Чек-лист готовности дела

- [ ] Выбрана концепция, утверждена «библия» в `docs/cases/`.
- [ ] `case.json`: валидатор зелёный, e2e кратчайшей победы есть.
- [ ] `art/ASSETS.md`: 0 заглушек, контакт-листы показаны.
- [ ] Хотспоты выставлены в S17.
- [ ] Озвучка сгенерирована, сверена с текстом дела.
- [ ] Музыка: переиспользована или готова своя.
- [ ] Владелец сыграл партию на телефоне, замечания закрыты.
- [ ] STATUS, devlog, CHANGELOG, MANUAL-TEST-QUEUE обновлены; PR влит в `main`.

## Затраты на одно дело (ориентир)

| Что                                             | Ориентир                                                                                         |
| ----------------------------------------------- | ------------------------------------------------------------------------------------------------ |
| Текст «библии» (чат-планировщик + самопроверка) | в рамках подписки                                                                                |
| Картинки (агент)                                | ~25–40 изображений                                                                               |
| Речь (Cartesia / ElevenLabs)                    | 8 дорожек, ~1,5 мин, одна попытка на дорожку                                                     |
| Музыка и эффекты ElevenLabs (агент, по API)     | 0 (переиспользование) или 1–2 трека минимальной длины + несколько эффектов, одна попытка на файл |
| Время владельца                                 | выбор концепции ~15 мин, одобрение арта ~15 мин, партия на телефоне ~40 мин                      |
