# ADR-016: Подготовка и постепенное подключение арта пилота

**Дата:** 2026-11-12 · **Статус:** принято

## Контекст

Есть четыре оригинала PNG 1024×1536, включая исправленный кабинет. Владелец отложил физическую проверку пакета M2 и разрешил продолжить. Старые зоны осмотра размечены по заглушкам.

## Варианты

Ждать весь комплект либо подключать готовые изображения вместе с соответствующей разметкой. Выбран второй вариант, с явной маркировкой оставшихся заглушек.

## Решение

Первый шаг M3 — обложка и три локации. tools/build-pack.ts реализует только подготовку арта sharp по явному манифесту art/pilot/manifest.json; сборка/публикация ZIP остаётся M5. Без генерации и внешних вызовов. Оригиналы сохраняются, выход — WebP q80, обложка 720×1080, локации 1080×1620 согласно арт-библии. Небольшое увеличение исходных локаций нужно для согласованных размеров валидатора; это не добавляет исходной детализации.

Готовность изображения определяется манифестом: подпись заглушки убирается только у готовых ресурсов. Зоны осмотра пересчитываются по новым рисункам. Над картинками не рисуются постоянные плашки с названиями объектов/стрелки; доступные имена элементов управления и контур клавиатурного фокуса сохраняются. Выданные факты и лимиты пока остаются прежними. Второй уровень поиска скола по ADR-012 — следующий отдельный шаг со схемой/движком/миграцией; не выдавать подключение картинки за его выполнение.

## Последствия

Манифест и сборка проверяют пути и размеры. Приложение содержит WebP и работает офлайн; PNG не копируются в APK. Нужны повторная проверка ресурсов, e2e действий и скриншоты на двух размерах. Физическая проверка M2 не блокирует этот разрешённый шаг, но остаётся в MT-014. Вопрос владельцу в STATUS: оценить компоновку новых локаций на телефоне, когда вернётся к проверке.
