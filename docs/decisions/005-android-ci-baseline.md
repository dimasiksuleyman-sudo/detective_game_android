# ADR-005: Android 26+, версия каркаса и единый CI

**Дата:** 2026-11-11 · **Статус:** принято

## Контекст

Capacitor 8.6.0 генерирует minSdk 24 и versionName 1.0. План требует Android 8+ (API 26), а рабочая версия приложения пока 0.0.1. Нужна последовательная проверка до выдачи APK.

## Рассмотренные варианты

1. Оставить генерируемые значения — противоречит целевой платформе и смешивает каркас с будущим релизом 1.0.
2. Задать параметры проекта явно и выполнять проверки одним CI-job — просто проследить, что APK получен после всех обязательных проверок.
3. Разнести проверки и APK на независимые job — быстрее при параллельном запуске, но сложнее связать выдачу артефакта с успешной проверкой.

## Решение

- Capacitor 8.6.0; minSdk 26, compile/target SDK 36 из шаблона, Android Gradle Plugin 8.13.0, Gradle Wrapper 8.14.3, JDK 21.
- Android versionCode 1 / versionName 0.0.1 соответствует package.json. appId остаётся временным по ADR-004.
- В manifest сразу фиксируются портретная ориентация и запрет cleartext; разрешение только INTERNET, без микрофона и датчиков на M0.
- GitHub Actions выполняет npm ci → lint → typecheck → unit → build web → Playwright → cap sync → assembleDebug в одном job с правами contents:read. APK и браузерные результаты доступны отдельными артефактами. Секреты не нужны.
- В setup-android явно задавать `packages: platform-tools`: значение по умолчанию включает снятый с публикации пакет `tools` и ломает установку (подтверждено первым CI). Полные тексты SDK-лицензий не печатать в лог CI.
- Использовать build-tools 35.0.0 (ожидается AGP 8.13), platform android-36. Android SDK локально хранится вне git; local.properties игнорируется.

## Последствия

- Поддержка Android 8+ соответствует плану. Совместимость на физическом телефоне подтверждает MT-001.
- Это debug-подпись средствами Android SDK, не release-ключ владельца. Нужны отдельные настройки релиза на M4.
- Действия CI закреплены на стабильных major-версиях; версии приложения и npm-зависимостей фиксированы точно. Обновления инструментов требуют нового прогона проверок.
