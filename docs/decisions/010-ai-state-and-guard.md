# ADR-010: Guard, озвучивание предъявления и совместимость сохранения

**Дата:** 2026-11-11 · **Статус:** принято

## Контекст

ИИ не должен менять правила, открывать чужие факты или расходовать реплику при фолбэке. Уже существуют партии M1; учёт денег должен переживать перезапуск.

## Рассмотренные варианты

1. Сохранять сырой ответ или полный HTTP-запрос — риск утечки ключа и смешения канона с текстом модели.
2. Отдать слом модели — нарушает детерминированность.
3. Передать модели только срез знаний, guard-ответ и отдельно подтверждённые движком события — выбран этот вариант.

## Решение

- promptBuilder явно перечисляет разрешённые поля. До слома тайна представлена только topic/lie; после конкретного брейкпоинта — только соответствующая truth. solution, timelineTruth и isCulprit не сериализуются. История — последние 8 пар только текущего игрока/подозреваемого; не все его улики.
- JSON допускает только одно Markdown-обрамление, не произвольное извлечение JSON из текста. Чужие id отбрасываются; стресс ограничен -1…2, эмоция — белым списком; текст ≤400 по границе предложения.
- Пилот не содержит состояния полного признания в убийстве. Эвристика отвергает признания, обвинения и мета-текст даже после частичного слома. Это эвристика, не доказательство отсутствия любых выдумок или догадок модели. Факты блокнота всегда канонические.
- Фолбэк детерминированный, без игрового действия: случайность не нужна для M2 и затрудняла бы воспроизводимость. Текст ошибки и офлайн-вопросы остаются доступны.
- Для предъявления сначала чистый preview reduce определяет реакцию/открываемые факты. ИИ получает только этот разрешённый результат. После guard применяется PRESENT_CLUE с озвученной репликой, а правила и факты вычисляются движком заново. При ошибке запрос не списывает реплику; улику можно предъявить классическим способом в той же партии, отключив озвучивание отдельной галочкой. Это не требует удаления ключа и сохраняет офлайн-первую работу предъявления.
- В GameState добавлены mode, aiUsage и emotions игрока; старое сохранение M1 получает defaults classic/пустой учёт/пустые эмоции без потери находок. Формат case.json не меняется.
- RECORD_AI_USAGE сохраняет только численные метрики и флаг неизвестной стоимости, независимо от успешности игрового ответа. Эти данные не раскрывают факты и не меняют лимит хода. После успешного слома движок не позволяет эмоции модели скрыть состояние broken.
- Нативный запрос отменяется при сворачивании; даже поздний ответ не применяется к другому ходу. Факт отмены не гарантирует, что провайдер не списал средства.
- M1 остаётся в очереди ручной проверки; M2 разрешён владельцем «го дальше» с явно сохранённым ограничением STATUS.

## Последствия

Тесты проверяют отсутствие скрытых данных и историю по снимку, guard и ошибочные ответы, повторы, отмену, стоимость, совместимость M1, безопасное хранение и UI на MockAiClient. Физическая проверка ключа и реальных моделей остаётся владельцу. Схема дела и сюжет не изменены.
