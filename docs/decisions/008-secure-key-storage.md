# ADR-008: Защищённый ключ BYOK и границы тестовой подмены

**Дата:** 2026-11-11 · **Статус:** принято

## Контекст

M2 требует хранения ключа в Android Keystore и полной работоспособности браузерных тестов без настоящих ключей. Владелец разрешил M2 сообщением «го дальше»; физическая приёмка M1 ещё не получена и остаётся в STATUS.

## Рассмотренные варианты

1. localStorage/Preferences — просты, но не соответствуют требованию секретности на Android.
2. Самописный плагин Keystore — большой объём кода и проверки криптографии.
3. @aparajita/capacitor-secure-storage 8.0.1 — совместим с Capacitor 8; Android-исходник использует AndroidKeyStore и AES/GCM/NoPadding. Выбран этот вариант.

## Решение

- Ключ читается/пишется только через src/platform/secureStorage.ts. На native ошибка не приводит к переходу в sessionStorage. Ключ не помещается в Zustand, партию, настройки IndexedDB, промпт или отчёт.
- На web — sessionStorage с явным предупреждением «режим разработки». Это не шифрование и не защита от кода того же origin.
- Вставка из буфера только по кнопке, через src/platform/clipboard.ts и @capacitor/clipboard 8.0.1. В поле ключ маскирован, после проверки/удаления очищается; при сворачивании настроек также очищается.
- Проверенный ключ сохраняется только после успешной проверки; исходный сохранённый ключ не заменяется при неудачной проверке нового.
- Android allowBackup=false; диагностическое логирование Capacitor loggingBehavior=none, чтобы мост не печатал аргументы секретного хранилища. В приложении сырые HTTP-ошибки не логируются; транспорт возвращает только коды ошибок.
- E2E имеют отдельную сборку mode=e2e в dist-e2e и только MockAiClient. Production dist строится отдельно и используется Capacitor; query-параметр не может включить мок в production APK. Ни один тест не вызывает реальные модели.
- Транзитивные iOS/Keyboard-зависимости плагина не означают добавление iOS-цели: приложение по-прежнему Android.

## Последствия

Keystore, удаление, перезапуск и отсутствие ключа в Logcat проверяет владелец в MT-004/010. Код и web-тесты не доказывают физическую работу Keystore. Тестовая сборка не публикуется как APK. Release-подпись владельца не требуется и не используется.
