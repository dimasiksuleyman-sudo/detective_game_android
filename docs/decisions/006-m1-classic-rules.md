# ADR-006: Уточнения классических правил и проверяемость пилота

**Дата:** 2026-11-11 · **Статус:** принято

## Контекст

M0 принят владельцем. Для M1 нужны однозначные переходы и проверяемая решаемость; текст плана оставляет некоторые пограничные случаи открытыми.

## Рассмотренные варианты

1. Передавать правила UI — быстро, но обход через прямой адрес или восстановление сохранения нарушает ограничения.
2. Проверять каждое действие чистым движком, а UI использовать как представление — воспроизводимо, подходит unit-тестам и будущему ИИ.
3. Определять доказанность мотива/способа/возможности поиском слов — хрупко; использовать разрешённое планом поле proves — проверяемо.

## Решение

- Все ограничения проверяет reduce. Один ход — до 2 разных зон одной локации либо до 3 реплик одному подозреваемому. Повторный осмотр/вопрос не расходует лимит; предъявление можно повторять для давления.
- Тон доступен и в классическом режиме: иначе достижение порогов зависело бы от числа оставшихся вопросов. Стресс вопроса — stressDelta из контента, дополнительного повторного +1 по словам нет.
- Порог брейкпоинта проверяется до изменения стресса предъявлением. Недостаток стресса даёт +2; требуемые факты обязательны, ignoreStress отменяет только стресс.
- «Адвокат» закрывает подозреваемого на весь следующий собственный ход игрока. В начале следующего после него хода стресс ровно 6; остальные значения спадают на 1.
- Правильные три варианта без ключевого доказательства дают одну поблажку за партию, включая случай приложенных неключевых находок. Повторная необоснованная попытка исключает игрока.
- В финальной фазе каждому оставшемуся даётся одна попытка без выбывания; для победы сохраняется требование ключевого доказательства. Все выбывшие означают немедленный финал без победителей. Решение и хронология доступны только после конца партии.
- Одна публичная карточка на id даёт +1 первому опубликовавшему; одна ключевая улика даёт +2 каждому нашедшему, один слом подозреваемого +1, независимо от числа его тайн.
- В Fact v1 добавляется необязательное proves: motive/method/opportunity. Пилот размечает существующие факты; сюжет, solution.keyEvidence и связи не меняются. Валидатор проверяет достижимый key-факт каждого вида.
- Длинные офлайн-реплики из исходного текста объединяются точками с запятой без изменения сведений, чтобы соответствовать пределу 3 предложений.
- Изображения M1 — цветные WebP нужных размеров, подписи отрисованы UI, а не запечены. Исключение требования «без арта» не нужно: это предусмотренные roadmap заглушки.
- Zod, Zustand, idb-keyval и Capacitor App подключаются на M1. Сохранение подтверждается перед показом результата действия; повреждённое сохранение не заменяется молча.
- Старт из общей страницы без партии безопасен. Прямые адреса не обходят передачу и не открывают финал. При восстановлении/сворачивании личная информация закрывается, в том числе в одиночном режиме при продолжении.
- Ветка M1 создана от принятого M0, чтобы сохранить историю до слияния PR M0. Сам PR M0 автоматически не сливается.

## Последствия

Тесты фиксируют перечисленные варианты. Новые поля описаны в схеме и пилоте. Вопросы трактовок вынесены в STATUS для владельца. Реальный ИИ не подключается; подготовленное действие результата ИИ принимает только разрешённые факты, а клиент появится на M2.
