# ADR-022: APK собирает только владелец, в облаке не собирается

**Дата:** 2026-11-12 · **Статус:** принято · **Заменяет:** ADR-007

## Контекст

CI собирал debug APK при изменениях `android/` и зависимостей, агент тоже собирал APK у себя. Владелец всё равно собирает и запускает игру в своей Android Studio на Windows, а публиковать в магазины будет оттуда же. Облачные APK подписаны другим debug-ключом, поэтому их установка поверх локальной сборки ломается (`INSTALL_FAILED_UPDATE_INCOMPATIBLE`), а сама сборка тратит минуты CI.

## Решение

- Из `.github/workflows/ci.yml` убраны JDK, Android SDK, `cap sync`, Gradle и выгрузка `android-debug`. Workflow переименован в «Проверки»: lint, типы, unit с покрытием, валидатор, web-сборка, production-проверка, e2e.
- Агент APK не собирает ни в CI, ни у себя. Перед закрытием этапа он проверяет `npm run build` и `npx cap sync android` (проверка, что нативный проект синхронизируется), а владельцу даёт команды обновления из `HOWTO-run.md`.
- Версию (`versionName`/`versionCode`) агент по-прежнему поднимает при заметных изменениях, а `CHANGELOG.md` описывает версии, которые владелец соберёт у себя.

## Последствия

- Нативная часть Android (Gradle, плагины) автоматически не компилируется: ошибку сборки увидит владелец в Android Studio. Если правка затрагивает `android/` или нативные плагины, агент явно пишет об этом в PR и в MANUAL-TEST-QUEUE.
- Старые ссылки на CI-артефакты APK в devlog и CHANGELOG — история, для установки не используются.
