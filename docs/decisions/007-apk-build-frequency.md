# ADR-007: Частота сборки APK при локальном запуске владельцем

**Дата:** 2026-11-11 · **Статус:** принято

## Контекст

Владелец собирает приложение в Android Studio на своём ПК и спросил, зачем дублировать APK в облаке. AGENTS.md требует успешную debug-сборку перед завершением этапа локально или в CI, но не требует повторять её после правки каждого документа.

## Рассмотренные варианты

1. Собирать APK при каждом push, включая документацию — долго, не добавляет проверки нативного кода.
2. Полностью убрать проверку Android — можно пропустить несовместимость нативной зависимости.
3. Проверять Android при изменениях оболочки/зависимостей, вручную по необходимости; веб-проверки сохранять — выбран этот вариант.

## Решение

- В CI APK собирается при изменении android/, package.json, package-lock.json или capacitor.config.ts. Ручной workflow_dispatch всегда собирает APK.
- Изменения только документации, тестов или веб-кода проходят lint/typecheck/unit/coverage/content/build/e2e без переустановки SDK и Gradle-сборки. Это не отключает тесты и не выдаёт пропущенную APK-сборку за успешную.
- Для закрытия этапа остаётся обязательным наличие реальной успешной debug-сборки. Для M1 она получена локально и в CI; запуск конечной версии на телефоне подтверждает владелец.
- Результаты APK привязаны к конкретному исходному коммиту, артефакты не называются сборками более поздних изменений. Для актуального локального UI владелец выполняет npm.cmd run android:sync и Run в Android Studio.

## Последствия

Правки отчёта не требуют повторной сборки APK. При добавлении новых источников native-конфигурации нужно расширять фильтр. Для полного APK после веб-изменений доступна кнопка Run workflow. Критерии этапа и обязательные тесты сохраняются.
