## 1. Стек (зафиксирован, см. ADR-001)

| Слой | Выбор | Комментарий |
|---|---|---|
| Оболочка | **Capacitor** (актуальная стабильная) | только Android на старте |
| UI | **React + TypeScript (strict) + Vite** | |
| Роутинг | React Router (MemoryRouter или HashRouter) | |
| Состояние | **Zustand** | стор поверх чистого движка |
| Стили | CSS Modules + CSS-переменные (токены цветов/шрифтов) | Tailwind — допустимо, если агент обоснует в ADR |

## 3. Ключевые архитектурные решения

### 3.1. Движок — чистая функция (ADR-003)
- `GameState` полностью сериализуем в JSON. Все изменения — через `engine.reduce(state, action)`.
- Действия: `START_GAME`, `BEGIN_TURN`, `SEARCH_HOTSPOT`, `ASK_OFFLINE_QUESTION`, `ASK_AI_QUESTION_RESULT` (результат ИИ уже провалидирован guard'ом), `PRESENT_CLUE`, `PUBLISH_TO_BOARD`, `ACCUSE`, `END_TURN`, `ADD_NOTE`.
- Асинхронщина (вызов ИИ) — в сторе/сервисе: вызвать ИИ → guard → диспатч `ASK_AI_QUESTION_RESULT` с уже проверенными данными.
- Это даёт: 100% покрытие правил unit-тестами, сохранение = `JSON.stringify(state)`, воспроизведение партии по логу действий.

### 3.2. Разделение знания (почему ИИ не может проговориться)
Промпт подозреваемого собирается **из среза знаний на текущий момент** (`docs/04-ai-prompts.md`): модель получает только легенду и те факты, которые персонаж готов раскрыть сейчас. Правды о скрываемом (и о том, кто убийца) в промпте нет, пока персонаж не «сломан» соответствующей уликой.

### 3.3. ИИ-клиент
- OpenAI-совместимый API aitunnel. Базовый URL: `https://api.aitunnel.ru/v1` (проверено: CORS разрешает запросы из WebView, `access-control-allow-origin: *`). Агент сверяет URL и параметры с актуальной документацией aitunnel и фиксирует в devlog.
- Вызов: `POST /chat/completions`, `response_format: {type: "json_object"}` (если модель поддерживает `json_schema` — использовать его), `temperature: 0.8`, `max_tokens: 400`, **reasoning выключен** (точный параметр — по документации aitunnel; думающие токены оплачиваются как вывод).
- Без стриминга в v1.0 (ответ — JSON, короткий; показываем индикатор «печатает…»).
- Таймаут 20 с, 1 повтор, при второй неудаче — запасная модель (если включена) или вежливый фолбэк «Подозреваемый молчит. Попробуйте спросить иначе» **без списания реплики**.
- Ответ содержит заголовки `cost-rub` и `balance` (они открыты через CORS `expose-headers`) → показываем стоимость реплики в debug-панели и баланс в настройках.
- Модели по умолчанию (меняются в конфиге/настройках): основная `qwen3.7-flash`, запасная `deepseek-v4-flash`. Финальный выбор — по итогам бенчмарка на этапе M2 (ADR).
- Интерфейс `AiClient` с реализациями `AitunnelClient` и `MockAiClient` (детерминированные ответы по шаблону — для тестов и для разработки без ключа).

### 3.4. Ключ пользователя (BYOK, ADR-002)
- Экран настроек: поле ключа (маскировано), «Вставить из буфера», «Проверить ключ» (минимальный запрос → показать баланс из заголовка), «Удалить ключ».
- Хранение — только secure storage (Android Keystore). Не в `localStorage`, не в сохранении партии, не в логах, не в отчётах об ошибках.
- Запросы идут **напрямую** с телефона в aitunnel; наши серверы ключ не видят. Это нужно отразить в политике конфиденциальности.
- Ссылка «Где взять ключ?» → короткая инструкция (регистрация на aitunnel, пополнение, создание ключа).

### 3.5. Контент: встроенные и скачанные дела
- Встроенные дела и труппа — в `public/` (работают офлайн сразу после установки).
- Скачанные паки — в `Directory.Data/packs/{caseId}/{version}/`. Пути к картинкам → `Capacitor.convertFileSrc()`.
- Каталог: `GET https://<server1>/packs/catalog.json` при запуске (если есть сеть), кэшируется. Формат — `docs/08-content-pipeline.md`.
- Каждый пак проверяется: sha256 из каталога, `schemaVersion` и `minAppVersion`, Zod-валидация `case.json`. Ошибка → пак не регистрируется, пользователю «Не удалось загрузить дело, попробуйте позже».
- Дела ссылаются на актёров труппы по `actorId`. Пак может содержать новых актёров (`troupe/` внутри пака) — они добавляются в локальную библиотеку.

### 3.6. Платформенные обёртки
Каждый модуль `src/platform/*` экспортирует одинаковый интерфейс для Android и браузера. В браузере:
- secure storage → sessionStorage (+ баннер «режим разработки»);
- голос → недоступен (кнопка микрофона скрыта, `isAvailable() = false`);
- датчики → кнопки-имитаторы в debug-панели;
- вибрация → no-op.
Это позволяет пройти всю игру в браузере и тестировать её Playwright'ом.

### 3.7. Android-специфика
- Портретная ориентация, полноэкранный режим с безопасными отступами (safe-area).
- Кнопка «Назад»: из экранов хода — возврат в хаб хода; из хаба — диалог «Выйти в меню? Партия сохранится».
- `appStateChange` (свернули приложение) во время хода → при возврате показать экран передачи (защита тайной информации).
- Разрешение микрофона — запрашивается при первом нажатии на кнопку микрофона, с пояснением.
- Сеть: `INTERNET` permission; cleartext запрещён.
- Подпись release-APK/AAB: keystore хранится у владельца, не в репозитории; инструкция — в `HOWTO-run.md`.

### 3.8. Производительность
- Картинки WebP; портреты ≤ 768×1152, локации ≤ 1080×1620, улики 512×512.
- Предзагрузка всех эмоций текущего подозреваемого при входе в допрос.
- Ленивая загрузка экранов (React.lazy).
- Цель: холодный старт < 3 с, переходы 60 fps на бюджетном устройстве (проверяет владелец, см. `07-testing.md`).

## 4. Серверы владельца
- **Сервер №1 — раздача контента**: nginx, HTTPS (Let's Encrypt), статические `catalog.json` и zip-паки, gzip, `Cache-Control` (каталог — 5 минут, паки — immutable по версии), CORS `*` на GET. Больше ничего на старте.
- **Сервер №2 — производство контента**: Node-скрипты из `tools/` (генерация черновика дела через сильную модель, валидатор, сборка паков, публикация на сервер №1 по rsync/ssh). В будущем — бэкенд подписок и ИИ-прокси для подписчиков (этап M7).

## 5. Будущее: подписка (этап M7, не делать раньше)
- Google Play Billing через RevenueCat (`@revenuecat/purchases-capacitor`) — для зарубежной аудитории.
- **RuStore Billing** — для РФ (Google Play-платежи у российских пользователей не работают). Готового плагина под Capacitor нет → свой нативный плагин-обёртка над RuStore SDK.
- Подписчик ходит в ИИ через наш прокси на сервере №2 (наш ключ, лимиты на устройство/подписку, проверка покупки на сервере). BYOK остаётся как альтернатива.
- Архитектурный задел уже сейчас: `AiClient` — интерфейс; добавится `ProxyAiClient`.

Уточнения M2: см. ADR-008/009/010. API-id моделей исправлены по публичным страницам; проверка ключа выполняется через GET /v1/aitunnel/balance без генерации. Фактический бенчмарк и отключение reasoning на реальном ключе пока не подтверждены. Фолбэк детерминированный; учёт стоимости включает отклонённые попытки и переживает перезапуск.

## Подготовленная озвучка встроенного дела (ADR-018)

Аудио в public/cases/<id>/audio/: MP3 и sidecar manifest.json (текст/голос/длительность/размер/хеш). src/content/narration.ts сопоставляет запись с актуальным текстом; src/components/NarrationPlayer.tsx показывает явные controls только в разрешённых экранах, src/platform/audio.ts обеспечивает одну дорожку и остановку при lifecycle/unmount. Схема дела и сохранения не изменены; ключ Cartesia только в ручной генерации Actions, не в runtime приложения. Автотесты работают с готовыми файлами без TTS-вызовов.

## Осмотр деталей и миграция (ADR-019)

Case schema v2: clue.inspection с прямоугольными областями/наблюдениями. INSPECT_CLUE принимает clueId/x/y, проверяет владение, фазу и область, записывает Player.inspectedDetails и выдаёт канонические факты без расхода бюджета. content/inspectionKnowledge.ts задаёт ограничения gated-фактов для движка и ИИ; concealedTerms используются только пост-фильтром. Сохранение envelope v2 читается вместе с v1 по прежнему storage key, старые известные факты не отбираются и помечают соответствующую деталь изученной. Приложение 0.3.0/code4, обратно открывать новое сохранение старым приложением нельзя.
