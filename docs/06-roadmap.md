# 06. Roadmap: этапы и критерии готовности

Работать строго по порядку. Этап закрыт, когда выполнены **все** критерии и обновлены `STATUS.md`, `MANUAL-TEST-QUEUE.md`, итоговый devlog этапа.

Общие критерии для каждого этапа: lint, typecheck и unit-тесты зелёные; CI зелёный; нет ключей в репозитории; документация обновлена.

---

## M0. Каркас проекта и дисциплина
**Задачи**
- Vite + React + TS (strict) + ESLint + Prettier + Vitest + Playwright.
- Capacitor, платформа Android (`android/` в репозитории), appId `ru.<владелец>.interrogation` (уточнить у владельца, до этого — `com.example.interrogation`, отметить в «Открытых вопросах»).
- Структура папок из `02-architecture.md`, пустые модули с комментариями-заголовками.
- Тема (CSS-токены из `05-art-bible.md`), шрифты (с открытой лицензией, напр. для заголовков — моноширинный «печатная машинка», для текста — читаемый с кириллицей; лицензии записать в `docs/licenses.md`).
- `src/i18n/ru.ts`, роутер, заглушки экранов S01–S16 с навигацией.
- GitHub Actions: lint → typecheck → unit → build → e2e. APK в CI не собирается (ADR-024).
- `docs/HOWTO-run.md` заполнен; `.gitignore` (в т.ч. `.env*`, keystore).

**Готово, когда**
- `npm run dev` открывает приложение в браузере; по всем заглушкам экранов можно пройти.
- `npm test`, `npm run e2e` проходят.
- Debug APK собирается (локально или в CI); APK устанавливается на телефон владельца (ручная проверка №1 в очереди).

## M1. Движок + пилотное дело, режим «Классика» (без ИИ, без арта)
**Задачи**
- `src/content/schema.ts` (Zod) по `03-case-schema.md`.
- `case.json` пилота «Синяя сова» из `docs/cases/case-001-blue-owl.md`; картинки-заглушки (цветные прямоугольники с подписью).
- `tools/validate-case.ts` (правила 1–8) + unit-тест «встроенные дела валидны и решаемы».
- Движок (`src/game/`): все действия из `02-architecture.md` §3.1, стресс, брейкпоинты, обвинение, выбывание, финальное обвинение, подсказки, очки.
- Экраны: S02–S14 функционально (без красоты): передача с удержанием, хаб хода, обыск с хотспотами, допрос офлайн-вопросами и предъявлением улик, блокнот (4 вкладки), доска, обвинение, финал.
- Рендер документов (`DocumentRender`) для всех шаблонов пилота.
- Автосохранение и «Продолжить».
- Защита при сворачивании (экран передачи при возврате).

**Готово, когда**
- Unit-тесты покрывают все правила движка (цель ≥ 90% строк `src/game`).
- e2e: «одиночная партия до победы» (скрипт проходит дело кратчайшим путём) и «2 игрока: ошибочное обвинение → выбывание → второй побеждает».
- Перезапуск приложения посреди партии → «Продолжить» восстанавливает состояние.
- Владелец может пройти дело на телефоне (ручная проверка).

## M2. ИИ-допрос с ключом пользователя
**Задачи**
- Экран настроек S15: ключ (secure storage), «Проверить ключ», баланс, выбор модели (расширенные), «Удалить ключ», инструкция «Где взять ключ».
- `src/ai/`: `AitunnelClient`, `MockAiClient`, `promptBuilder`, `responseParser`, `guard`, конфиг.
- Режим допроса «ИИ» в настройке партии (доступен только с проверенным ключом); в чате — поле ввода, выбор тона, индикатор «печатает…», ошибки сети.
- Предъявление улик в ИИ-режиме (исход решает движок, ИИ озвучивает).
- Debug-панель: стоимость последней реплики (`cost-rub`), сумма за партию.
- `tools/ai-smoke.ts` + бенчмарк трёх моделей (`04-ai-prompts.md` A.7) → ADR «модель по умолчанию». **Нужен ключ от владельца** — если ключа нет, сделать всё на моке и отметить в «Открытых вопросах».

**Готово, когда**
- Unit-тесты guard и promptBuilder (включая снапшот: правды и `isCulprit` нет в промпте до слома).
- e2e: ИИ-допрос с `MockAiClient` (вопрос → ответ → факт в блокноте; предъявление → слом).
- Без сети: понятная ошибка, реплика не списана, офлайн-вопросы работают.
- Ключ не попадает в логи, сохранения, отчёты (тест на маскировку).

## M3. Арт и «живость»
**Задачи**
- Подключить картинки пилота и труппы (владелец генерирует по `05-art-bible.md`; агент — `tools/build-pack.ts`-часть для ресайза/WebP и проверки размеров).
- Портрет с эмоциями: плавная смена (кроссфейд 200–300 мс), «дыхание» (scale 1.00↔1.01), моргание (если есть `blink`), дрожь при стрессе ≥ 8, виньетка по стрессу.
- Обработка «фото из дела» для жертвы (CSS: сепия, рамка-полароид, скрепка).
- Брифинг, обложки, главное меню, доска на пробке, экран передачи — финальный вид.
- S17 — редактор хотспотов (debug): тап → координаты → копирование JSON.
- **Принято по уточнению владельца, ещё не реализовано:** дополнительный point-and-click осмотр важных улик (статуэтка → скол крупным планом), ADR-012. Факт открывается после самостоятельного обнаружения детали; прямые подсказки и преждевременные раскрытия через описание/ИИ исключены. При реализации обновить схему по ADR, валидатор, дело и сохранения. Это дополнение не закрывается наличием обычных хотспотов M1.
- Звуки (опционально): дождь, печатная машинка на новый факт; настройка звука.
- Выполнен первый набор озвучки: восемь локальных MP3 Sergei (брифинг, существующие подсказки и финал), явное воспроизведение и остановка в фоне/при уходе, ADR-018. Полная телефонная проверка — MT-015.
- Идея владельца: озвучка вступления/брифинга, Cartesia.ai выбран и голос Sergei утверждён, восемь дорожек подключены (ADR-017/018). Формат будущих скачиваемых аудиопаков уточняется в M5.

**Готово, когда**
- Все экраны в финальном стиле; скриншоты всех экранов на 360×800 и 412×915 приложены к devlog.
- Нет «прыжков» вёрстки при загрузке картинок; предзагрузка эмоций.

## M4. Android-полировка и голос
**Задачи**
- Голосовой ввод (`@capacitor-community/speech-recognition`, ru-RU), запрос разрешения с пояснением, индикатор записи, редактирование распознанного текста перед отправкой.
- Кнопка «Назад», keep-awake во время партии, статус-бар, safe-area, портретная блокировка, иконка, сплэш.
- Вибрация: слом подозреваемого, новая улика, ошибка обвинения.
- Краткие тосты временных ошибок вместо большого постоянного блока (ADR-015); на время разработки владелец разрешил оставить текущий блок. Исключить повторение одинаковых сообщений, сохранить доступность и отдельный учёт затрат.
- Производительность на слабом устройстве (рекомендации из `02-architecture.md` §3.8).
- Release-сборка: подпись (keystore у владельца), versionCode/versionName, `CHANGELOG.md`.
- Политика конфиденциальности (черновик в `docs/privacy-policy.md`): ключ хранится на устройстве, запросы идут напрямую в aitunnel, голос распознаётся системой Android.

**Готово, когда**
- Весь чек-лист M4 в `MANUAL-TEST-QUEUE.md` пройден владельцем.

## M5. Паки дел и сервер
**Задачи**
- `src/content/packs.ts`: каталог, список «доступно для загрузки», скачивание с прогрессом, sha256, распаковка, регистрация, удаление пака.
- `tools/build-pack.ts`, `tools/publish-pack.ts`, `server/nginx/packs.conf` (`08-content-pipeline.md`).
- Второе встроенное или скачиваемое дело (контент готовит владелец по пайплайну) — проверка, что формат держит другое дело.

**Готово, когда**
- e2e: каталог с мок-сервера → скачивание → дело появляется → проходится.
- Повреждённый пак (sha256 не совпал / невалидный JSON) не ломает приложение.
- Владелец опубликовал пак на сервер №1 по инструкции и скачал его на телефон.

## PWA и языки (ADR-032) — после релиза RU в сторах
- **PWA (RU):** манифест, service worker, «Скачать для офлайна» по делам, `storage.persist()`, «Доступна новая версия», хостинг на сервере № 1 с HTTPS. Готово, когда: игра ставится с сайта на Android и iPhone, проходится в режиме полёта, сохранения переживают перезапуск браузера.
- **Языки:** словари интерфейса и выбор языка; перевод дела с проверкой полноты в валидаторе; озвучка, промпты ИИ и защита от утечек на каждый язык; второй ИИ-провайдер для зарубежных игроков. Первым — английский на одном деле. Готово, когда: дело проходится целиком на английском, тесты защиты от утечек есть для обоих языков.
