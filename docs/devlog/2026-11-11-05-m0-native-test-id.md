# 2026-11-11-05 — Проверка appId в нативном шаблоне теста

**Этап:** M0 · **Пункт roadmap:** корректный Android-каркас · **Коммит:** эта запись сопровождает исправление теста.

## Цель

Проверить сгенерированные Android-файлы перед передачей владельцу.

## Что сделано

При просмотре файлов Capacitor найден шаблонный instrumentation-тест: он ожидал пакет com.getcapacitor.app, хотя приложение имеет временный appId com.example.interrogation. Ожидаемое значение приведено к конфигурации приложения. Сам тест сохранён; проверки не отключались.

## Изменённые файлы

- `android/app/src/androidTest/java/com/getcapacitor/myapp/ExampleInstrumentedTest.java` — ожидаемый packageName соответствует фактическому APK.
- `docs/STATUS.md`, `docs/devlog/INDEX.md`, эта запись — результат просмотра и ограничения проверки.

## Команды

Перед коммитом: npm run lint, npm run typecheck, npm test. Результаты: lint/typecheck успешно, unit 2/2. Android-приложение не менялось, локальный APK из записи 04 остаётся актуальным по исполняемому коду.

## Тесты

Instrumentation-тест требует запущенного Android-устройства и здесь не исполнялся. Исправлено заведомо неверное значение шаблона, а не ожидаемое поведение приложения. E2E и debug APK проверяются CI после коммита.

## Проблемы и решения

Шаблон Capacitor не подставил appId в тест. Ожидаемое значение исправлено без удаления теста. При утверждении окончательного appId нужно обновить также эту проверку.

## Отклонения от плана

Нет; appId остаётся временным согласно ADR-004.

## Ручная проверка

MT-001 подтверждает установку и запуск приложения. Instrumentation-тест не выдаётся за пройденный; для его запуска на подключённом устройстве разработчик может выполнить `cd android && ./gradlew connectedDebugAndroidTest`.
