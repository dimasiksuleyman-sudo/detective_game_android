# 2026-11-12-08 — Реальный допрос на телефоне и очередь правок

**Этап:** M2, обратная связь владельца.

## Цель

Сохранить результаты реальной проверки и предложения, не исправляя приложение до завершения сбора ошибок.

## Что сделано

Владелец обновил ветку M2 (97fcbbf), успешно выполнил android:sync и проверил приложение на TECNO CAMON 30S / Android 16. Ключ вставляется, сохраняется, баланс проверяется. После закрытия приложения ключ сохранён, но пустое поле выглядит как потеря ключа: владелец просит звёздочки/явное состояние сохранения. Реальная модель отвечает разумно, ориентир владельца 0,01 ₽ за запрос. Название модели и отдельные численные задержки не сообщены. На скриншоте содержательный допрос о местонахождении подозреваемой; это не доказательство прохождения всех guard/канонических сценариев.

Предложение: 10 запросов на раунд каждому игроку; расчёт пяти игроков и 10 раундов даёт около 5 ₽ без повторов. ADR-013 фиксирует расхождение с текущими 1–4 игроками и тремя репликами. Код не изменён, исправления собираются пакетом.

## Изменённые файлы

ADR-013 — лимит и стоимость; STATUS — подтверждённые результаты, очередь и вопросы; MANUAL-TEST-QUEUE — частичные результаты MT-004/010; HOWTO — очередь правок; INDEX и эта запись — журнал.

## Команды

Чтение документов, форматирование; npm run lint, npm run typecheck, npm test перед коммитом.

## Тесты

Физическую проверку выполнил владелец; агент не делал платных запросов. Подтверждены ключ/баланс и осмысленный ответ. Перезагрузка телефона, удаление, отсутствие ключа в Logcat, офлайн и отмена ещё не подтверждены. Полный бенчмарк не выполнялся. APK для документации не собирается.

## Проблемы и решения

Пустое поле ключа после возврата вызывает сомнение, несмотря на сохранённый ключ: добавить явное маскированное состояние, не подставляя настоящий секрет в поле. Исправление пока только в очереди. Цена дана владельцем как оценка, не универсальный тариф.

## Отклонения от плана

Предложено расширение квоты по ADR-013. Изменения правил и максимум игроков не реализованы.

## Ручная проверка

Следующая отдельная проверка: в режиме полёта отправить свободный вопрос; получить понятную ошибку без списания игровой реплики. Затем продолжать остальные проверки по одному шагу с подтверждением владельца.

## Следующий шаг

Продолжить сбор результатов по одному действию. После завершения внести пакет исправлений, включая отображение сохранённого ключа и согласованные лимиты.
