# 2026-11-12-06 — Идея осмотра деталей улик

**Этап:** предложение для M3, без изменения приложения.

## Цель

Зафиксировать предложенный владельцем дополнительный point-and-click осмотр и отличить его от уже реализованных зон комнаты.

## Что сделано

Проверен GameApp: нажатие зоны вызывает SEARCH_HOTSPOT, открывает крупный план и сразу выдаёт улику с фактами. Отдельных зон на самой улике нет. Записан ADR-012 со сценарием «статуэтка → скол», предварительными правилами лимитов и повторных осмотров, доступностью и офлайн-работой. Вопрос о моменте открытия факта оставлен владельцу; код не изменён.

## Изменённые файлы

ADR-012 — предложение и последствия; 01-game-design — сценарий; 06-roadmap — дополнительный пункт M3; STATUS — готовность и открытый вопрос; HOWTO — доступность функции; MANUAL-TEST-QUEUE — будущий MT-012; INDEX и эта запись — журнал.

## Команды

Чтение GameApp.tsx и case.json, сравнение правил обыска. Перед коммитом: npm run lint, npm run typecheck, npm test.

## Тесты

Правка только документации. Обязательные проверки выполняются перед коммитом; e2e/APK повторно не требуются. Тесты нового поведения не заявляются, поскольку реализации нет.

## Проблемы и решения

Идея ранее осталась только в чате. Теперь отражена в документах с явным статусом предложения. Нельзя обещать поиск скола, если факт автоматически открыт раньше: при реализации потребуется отдельно согласовать выдачу фактов и при необходимости изменить схему/валидатор/сохранения.

## Отклонения от плана

Предложение расширяет M3, не заменяет существующие зоны M1; ADR-012. Действующие правила и данные не меняются.

## Ручная проверка

Будущий MT-012: попадание в деталь, увеличение, повтор без двойной награды, возврат, сохранение и офлайн. В текущей сборке недоступен.

## Следующий шаг

Получить решение о том, обязателен ли поиск детали для открытия факта; затем планировать реализацию. Проверка M2 продолжается независимо.
