# 2026-11-11-14 — Основа M2: ключ, срез знаний и безопасный контракт ИИ

**Этап:** M2 · **Пункт roadmap:** AI-клиент, promptBuilder/parser/guard, хранение, сохранение.

## Цель

Подготовить ИИ-допрос без передачи модели скрытого решения, с защищённым ключом и тестами без реальных запросов.

## Что сделано

- M2 разрешён владельцем «го дальше» после отчёта M1. Физическая приёмка M1 остаётся открытой, что явно записано в STATUS.
- Прочитаны актуальные правила и публичная документация aitunnel: контракт, reasoning, structured outputs, баланс, страницы трёх моделей. Найдены корректные API-id qwen3.7-flash и gemini-2.5-flash-lite; бенчмарк не выполнялся.
- Подключены @aparajita/capacitor-secure-storage 8.0.1 и @capacitor/clipboard 8.0.1. Android-код хранения проверен на AndroidKeyStore/AES-GCM. Native не откатывается в web storage при ошибке. Web — явно предупреждённая заглушка sessionStorage.
- loggingBehavior=none и allowBackup=false исключают диагностический вывод аргументов моста и системный backup приложения. Сырые ошибки API не попадают в UI/логи.
- promptBuilder перечисляет только публичные и разрешённые сведения одного подозреваемого, topic/lie до слома, соответствующую truth после, последние 8 пар только этого игрока с этим персонажем.
- Парсер допускает JSON и одно Markdown-обрамление. Guard ограничивает эмоцию/стресс/длину, фильтрует id и мета-текст/признания; канон блокнота остаётся у движка.
- AitunnelClient использует прямой HTTPS, Bearer только в заголовке, таймаут/отмену, фиксированный адрес и маскирует возможное эхо ключа. Ключ проверяется методом баланса без генерации.
- Service делает максимум две попытки основной модели, запасную только по настройке. Бесплатный игровой фолбэк не означает бесплатный запрос провайдера: стоимость и неизвестность учитываются отдельно.
- Старые сохранения M1 получают defaults mode/aiUsage/emotions. Метрики затрат сохраняются отдельным действием без расхода реплики и без секретных полей.
- MockAiClient остаётся единственным клиентом, вызываемым тестами. Тестовая сборка вынесена в dist-e2e, production dist не перезаписывается моковой сборкой.

## Тесты

68 unit-тестов прошли; строки движка 98,89%, ветви 90,04%. Положительные тесты контекста включают снимок и проверку отсутствия truth/isCulprit/solution до слома. Нативное хранилище проверялось через mock plugin; это не физическое доказательство Keystore. E2E интеграция записывается следующим шагом.

## Проблемы и решения

- URL-slug модели не равен API-id — исправлено по публичной информации, ADR-009.
- JavaScript \b/\w не описывают русские буквы — guard использует явный русский диапазон; тесты обнаружили и зафиксировали эти случаи.
- Цена принятого/отклонённого ответа сохраняется независимо от игрового лимита; отсутствие метаданных не выдаётся за нулевую стоимость.
- Production и e2e dist разделены, чтобы CI не собрал APK с MockAiClient.

## Отклонения от плана

ADR-008/009/010. Фолбэк детерминированный; проверка ключа без генерации; исправлены API-id, окончательная модель ждёт бенчмарка. Реальное качество и отключение reasoning не подтверждены.

## Ручная проверка

MT-004 и новый MT-010 для хранения, удаления, Logcat и реального ИИ на TECNO CAMON 30S / Android 16. Голос остаётся M4. Бенчмарк только вручную при наличии ключа; ключ не отправлять в чат.
