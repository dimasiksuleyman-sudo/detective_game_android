# 2026-11-12-33 — Git LFS для исходников ассетов

**Этап:** процесс · **Ветка:** `claude/lucid-wozniak-3iu7wi` от `main` (`08e6327`) · **ADR:** 027

## Цель

По решению владельца перенести хранение исходников арта и аудио в Git LFS до второго дела. Позже, при упоре в лимиты, — свой сервер или S3.

## Что сделано

- `.gitattributes`: `art/**/*.{png,jpg,jpeg,webp,mp3,wav}` → LFS. 65 файлов, закоммиченных раньше, явно исключены через `-filter`, чтобы не переписывать историю и чтобы `git status` у всех оставался чистым.
- `tools/check-lfs.ts` и `npm run lfs:check`: проверяет по индексу git, что каждый новый исходник — LFS-указатель. Добавлен в CI перед валидацией дела.
- Проверено:
  - новый файл в `art/` становится LFS-указателем;
  - старые файлы не считаются изменёнными;
  - файл, добавленный мимо LFS, проверка ловит (❌).
- `AGENTS.md` §8, HOWTO (раздел Git LFS), ранбук (шаг 0 закрыт), ADR-027 с планом переезда на сервер или S3.

## Изменённые файлы

- `.gitattributes`, `tools/check-lfs.ts`, `package.json`, `.github/workflows/ci.yml` — LFS и проверка.
- `AGENTS.md`, `docs/HOWTO-run.md`, `docs/CASE-RUNBOOK.md`, `docs/decisions/027-git-lfs-for-art-sources.md`, `docs/devlog/INDEX.md`, эта запись.

## Команды

`git lfs install --local`, пробное добавление файла (`git lfs ls-files`), `npm run lfs:check` (✅ 65 файлов и ❌ на поддельном файле), lint, typecheck, unit.

## Проблемы и решения

- Если просто добавить правило LFS к уже закоммиченным файлам, у всех с установленным Git LFS они сразу показываются изменёнными. Решение — явный список исключений `-filter` для 65 старых файлов.

## Ручная проверка

Владельцу один раз выполнить `git lfs install` на компьютере (HOWTO).
