# 2026-11-11-03 — Android и CI для M0

**Этап:** M0 · **Пункт roadmap:** Android, pipeline, инструкция сборки · **Коммит:** эта запись сопровождает Android/CI.

## Цель

Собрать настоящий debug APK и обеспечить повторяемую автоматическую проверку в GitHub Actions.

## Что сделано

- Сгенерирована и добавляется в git платформа Android от Capacitor 8.6.0.
- Согласованы minSdk 26, versionName 0.0.1, versionCode 1, портрет и запрет cleartext (ADR-005).
- Создан последовательный CI с линтом, типами, unit, web, e2e и APK; заданы артефакты android-debug и browser-results.
- Android command-line tools скачаны с официального dl.google.com, SDK установлен в рабочую директорию вне репозитория. Системные пакеты не менялись. Полный JDK установлен отдельно после диагностики.
- Проверен не только production preview: `npm run dev -- --port 5173 --strictPort` открыт через Chromium; заголовок стартового экрана найден.

## Команды

- `npx cap add android` — успешно.
- `npm run android:sync` — web build и cap sync успешны.
- SDK Manager: platform-tools, platforms;android-36, build-tools;35.0.0 — установлены.
- `./gradlew --no-daemon assembleDebug` с proxy-параметрами среды — выполняется; первый запуск не прошёл без javac; повтор с JDK выявил отсутствие CA прокси в новом truststore. Сборка повторяется с системным `/etc/ssl/certs/java/cacerts`. Итог APK будет в записи 04.

## Тесты

Браузерный шаг: 2 unit и 2 e2e, lint и typecheck прошли. Dev-сервер открыт в настоящем Chromium. Повторно перед коммитом прошли lint/typecheck, 2 unit и 2 e2e. Результаты APK/CI будут в итоговой записи 04.

## Проблемы и решения

В среде отсутствовал Android SDK. Скачаны официальные command-line tools, сохранены вне git. Новейший sdkmanager сообщает о переходе на Android CLI и сам использует системный proxy; установка пакетов завершилась успешно. Первая сборка остановилась: системный Java 21 не содержит javac (JRE, а не полный JDK). С официального Adoptium установлен Temurin JDK 21.0.13 в `/workspace/work/jdk21`, `JAVA_HOME` задан только процессу сборки. CI использует полный Temurin JDK через setup-java. Новый Temurin не доверяет CA облачного прокси: вместо отключения TLS указан системный Java truststore `/etc/ssl/certs/java/cacerts`. Локальному Gradle переданы параметры прокси из среды, без изменения репозитория и без отключения TLS.
