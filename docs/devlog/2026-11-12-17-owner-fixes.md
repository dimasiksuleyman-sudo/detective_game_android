# 2026-11-12-17 — Пакет правок после проверки владельцем

**Этап:** M2, исправления по команде «го».

## Цель

Внести согласованные изменения без повторения автоматизируемых проверок владельцем.

## Что сделано

В поле ключа показывается маскированный placeholder при сохранённом ключе, сам секрет в поле не возвращается. ИИ-форма расположена перед готовыми вопросами, готовые вопросы в ИИ-режиме свёрнуты, в классике открыты. Исключён повтор фразы о несписании в сетевой ошибке. Единый лимит разговора — три реплики в ИИ и три в классике, максимум пять игроков и пять цветов, сохранение принимает пять игроков. Художественные исходники остаются отдельно, новые картинки в игру не подключены. Тосты и Cartesia отложены по договорённости.

## Изменённые файлы

src/components/AiSettings.tsx — индикатор ключа; src/screens/GameApp.tsx — порядок UI, список игроков и общий лимит; src/i18n/ru.ts — централизованные тексты; src/game/engine.ts — лимиты и пятый игрок; src/persistence/save.ts — совместимое расширение сохранения; unit/e2e — новые сценарии. ADR-013, геймдизайн, STATUS/HOWTO/очередь и INDEX — документация.

## Команды

npm run lint, npm run typecheck, npm test; npm run e2e; npm run android:sync. Результаты ниже фиксируются после завершения. Облачный APK не требуется для этого пакета веб-правок, владелец собирает локально по ADR-007.

## Тесты

Добавлены проверки трёх реплик/блокировки четвёртой/сброса бюджета, классического лимита, пяти цветов/порядка ходов и roundtrip сохранения. E2E проверяет восстановление маски ключа после reload, свёрнутый список, три вопроса и новый ход, а также прежние сценарии. Только MockAiClient, без платных запросов.

## Проблемы и решения

Начальная проверка пятого игрока не прошла из-за пропущенного перехода briefing → handover в самом тесте; исправлена подготовка сценария, правило передачи не менялось. Промежуточное изменение квоты отменено после уточнения владельца; прежние проверки блокировки после трёх сохранены.

## Отклонения от плана

ADR-013 уточнён: общий бюджет реплик ИИ-хода, один подозреваемый, старые правила стресса. Максимум пять игроков. Неподтверждённое поведение главного меню после возврата не менялось без установленной причины.

## Ручная проверка

Только после новой установки проверить на телефоне маску сохранённого ключа и порядок элементов. Владелец не должен повторять проверенные автоматически классические сценарии. Полная перезагрузка телефона/Logcat и производительность остаются открытыми.

## Следующий шаг

Завершить автопроверки и выдать владельцу одно действие для обновления. M3 не закрывается этим пакетом.

## Уточнение во время работы

Владелец пересмотрел десять реплик из соображений баланса. До коммита вернули три в обоих режимах, сохранили общий бюджет и проверку четвёртой реплики. В e2e после reload уже открыт hash настроек, поэтому повторный поиск кнопки «Настройки» был ошибкой подготовки теста: убран повторный переход, проверка восстановления маски сохранена.

При первом финальном e2e-прогоне 21 из 22 прошли, один выявил гонку тестового помощника при переходе: он пытался раскрыть список, когда запрошенной кнопки ещё не было в новом экране. Исправлен помощник: ожидание нужной кнопки в DOM и раскрытие только её родительского details; force/паузы/пропуск тестов не используются. Затем повторён полный прогон.

Итог проверки пакета: lint/typecheck успешны, 71 unit прошёл, покрытие движка 98,90% строк / 90,12% ветвей, полный повторный e2e 22/22 на 360×800 и 412×915. Production-проверка и android:sync успешны, три native-плагина подключены. Скриншоты нового прогона — docs/devlog/assets/m2-fixes/, исторические M2 восстановлены. Новая физическая проверка UI владельцем ещё не выполнялась. Лимит — три реплики в обоих режимах.
