# 2026-11-11-11 — Стили классических экранов в CSS Modules

**Этап:** M1 · **Пункт roadmap:** соответствие архитектуре UI · **Коммит:** стили и эта запись вместе.

## Цель

Сохранить выбранный в архитектуре способ организации стилей перед окончательной передачей M1.

## Что сделано

Игровые стили, первоначально добавленные в global.css при прототипировании, перенесены в GameApp.module.css. Компонент использует ссылки styles.game/location/handover/document. Общая тема и шрифты остаются глобальными; видимые тексты и правила не менялись.

## Изменённые файлы

- src/screens/GameApp.module.css — стили функциональных экранов.
- src/screens/GameApp.tsx — подключение CSS Module и классов.
- src/theme/global.css — общая тема без дублирования игровых классов.
- docs/STATUS.md, docs/devlog/INDEX.md, эта запись — описание соответствия архитектуре и текущие проверки.

## Команды

Форматирование, lint, typecheck и unit перед коммитом. Production build и E2E повторяются в CI, поскольку имена CSS-классов изменились.

## Тесты

Предыдущий функциональный прогон: 24 unit, 10 e2e, валидатор и APK прошли. Изменение классов проверяется повторным CI; новые игровые функции не добавлены.

## Проблемы и решения

При прототипировании стили временно находились рядом с глобальной темой. В финальном коде M1 используется CSS Modules, как требует docs/02-architecture.md. Нового архитектурного выбора нет, ADR не требуется.

## Отклонения от плана

Нет; приводится в соответствие уже выбранному стеку.

## Ручная проверка

MT-009 остаётся обязательным после выдачи APK; результаты M0 не заменяют M1.

## Следующий шаг

Завершить CI, записать итог M1, остановиться перед M2.
