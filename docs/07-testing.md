# 07. Тестирование: что проверяет агент, а что — владелец

## 1. Агент (автоматически, в облаке / CI)
Приложение — веб-код внутри Capacitor, поэтому **почти всё** проверяется в браузере.

| Уровень | Инструмент | Что покрывает |
|---|---|---|
| Unit | Vitest | движок (все правила), Zod-схема, валидатор дел, promptBuilder, guard, парсер ответов, маскировка ключа, packs (sha256, распаковка) |
| Контент | `tools/validate-case.ts` | все встроенные дела валидны и решаемы |
| E2E | Playwright (Chromium, viewport 360×800 и 412×915) | полные партии, сохранение/восстановление, ИИ-допрос на `MockAiClient`, офлайн-режим (`context.setOffline(true)`), скачивание паков с мок-сервера |
| Визуал | Скриншоты Playwright | скриншоты всех экранов прикладываются к devlog этапа; агент сам просматривает их на предмет поломок вёрстки |
| Сборка | `npm run build` + `npx cap sync android` | веб-часть собирается и синхронизируется; APK собирает только владелец в Android Studio (ADR-024) |
| ИИ smoke | `tools/ai-smoke.ts` (вручную, нужен ключ) | реальные ответы моделей, стоимость, бенчмарк |

Чего агент **не может** проверить надёжно: эмулятор Android в облачном контейнере обычно недоступен (нет аппаратной виртуализации), а нативные функции работают только на реальном устройстве. Поэтому всё нативное — за обёртками `src/platform/` с веб-заглушками, а реальная проверка — у владельца.

## 2. Владелец (вручную, на реальном телефоне)
Агент ведёт очередь в `docs/MANUAL-TEST-QUEUE.md`: что проверить, как, ожидаемый результат. Владелец ставит ✅/❌ и пишет комментарий.

**Только на телефоне проверяются:**
- 🎙️ **Голосовой ввод** (распознавание русской речи, разрешение микрофона, работа без сети при скачанном языковом пакете).
- 🔐 **Хранилище ключа** (ключ сохраняется после перезапуска, не виден после «Удалить ключ»).
- 📳 Вибрация.
- 📐 Датчики для мини-игр: встряска, наклон, датчик света, микрофон (этап M6).
- ⬅️ Кнопка «Назад», сворачивание/разворачивание (экран передачи), блокировка экрана, keep-awake.
- 🐢 Производительность на бюджетном телефоне: плавность смены портретов, время запуска.
- ✈️ Режим полёта: игра «Классика» полностью проходима.
- 🤖 Реальный ИИ-допрос со своим ключом: качество русского, скорость, стоимость.
- 🖼️ Как выглядит на конкретном экране (вырезы, жесты навигации).

## 3. Как владелец устанавливает сборку
Инструкцию поддерживает агент в `docs/HOWTO-run.md`; кратко:
1. Скачать `app-debug.apk` из артефактов последнего прогона GitHub Actions (или из релиза).
2. На телефоне разрешить установку из неизвестных источников для браузера/файлового менеджера.
3. Установить, пройти пункты из `MANUAL-TEST-QUEUE.md`.

## Дополнительный осмотр деталей

Автоматически: факт отсутствует при находке, неправильные координаты/чужая улика/неактивная фаза отвергаются; попадание открывает только свой факт, повтор/масштаб не расходуют бюджет/очки; два игрока независимы, публикация предмета не открывает скрытые детали другому; old-save миграция сохраняет факты; guard не пропускает неоткрытый скол и не блокирует «сколько». Браузер: увеличение/прокрутка, реальные изображения, повторное открытие из блокнота и возврат, сохранение. На телефоне MT-012 проверяет только физическое удобство попадания/жестов и производительность, не повторяет весь набор автотестов.
